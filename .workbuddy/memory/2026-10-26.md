## 修「压到限位后反向退不出来」（同日）

现象：一直正转压到限位停车后，按反转动不了。

根因：`EnforceLimit()` 只判断"限位被压住"就 `GA_Stop`，**不看运动方向**。
退出时感应片还压在开关上 → `pos` 仍为 true → 每 50ms 又被打停，轴刚起步就被杀，表现为"按了没反应"。

修法：新增 `private int lastDir`（+1 正转 / -1 反转 / 0 无），在 `StartMove` 成功下发时置为 dir，
`StopAxis` 与 `EnforceLimit` 停车后置 0，`ShowDisconnected` 也清零。判断改为：

```csharp
bool intoPos = pos && lastDir > 0;
bool intoNeg = neg && lastDir < 0;
if (!intoPos && !intoNeg) return;   // 反向脱离时放行
```

**为什么不用速度符号判断**：按下反转后有一段减速过程，此时 `vel1` 仍为正，
用 `vel1 > 0` 会把正常的脱离动作误杀。用"下发的指令方向"才可靠。

行为矩阵：压正限位→正转被拦/运行中被停；压正限位→反转放行；不压限位→两向都放行。

## 关键纠正：限位映射与方向相反（同日）

用户反馈"现在的代码逻辑和你写的刚好相反"。反推结论：
**按【正转】走到底，压到的是 X1，不是 X0。** 即"正限位=X0、负限位=X1"这个标号
和"正转朝哪边走"是反的（电机方向或接线方向与坐标方向不一致）。

修法：**彻底放弃"正限位/负限位"这套命名**，改为按方向命名：

```csharp
private const short LIMIT_FWD_INDEX = 1;   // 正转（位置变大）走到底 → 压到 X1
private const short LIMIT_REV_INDEX = 0;   // 反转（位置变小）走到底 → 压到 X0
```

对应方法改名 `LimitFwdHit()` / `LimitRevHit()`，界面文字改为「正转端限位 X1」「反转端限位 X0」。
控件名仍是 `lblLimPos` / `lblLimNeg`（不改设计器字段名，减少改动面）。

**教训：限位配置必须按「方向」定义，不能按「正/负」定义。** 正/负是坐标概念，
和电机实际转向、限位物理位置没有必然对应，一问就绕。
若换线，只需把这两个数字对调。

## 加回零 + 轴2 设零点（同日）

用户问：想以原点开关建坐标系、要采编码器数据，但轴2 是开环电机没编码器怎么办。

**核心概念（要记住）**：这张卡是脉冲卡，**坐标系 = 规划位置 PrfPos**，不是编码器位置。
开环步进电机没有编码器完全不影响建坐标——卡发出的脉冲本身就是位置。
编码器只用于"实际位置校验/跟随误差"，不是坐标来源。

API 签名（dnfile 实解，与手册略有出入）：
- `GA_HomeSetPrmSingle(short axis, short mode, short dir, int offset, double rapid, double locat, double indexVel, double acc)` （**8 个参数**，手册写 11 个）
- `GA_HomeStart(short)`、`GA_HomeStop(short)`
- `GA_HomeGetSts(short, ref short sts, ref int, ref int, ref int)` — 0 未回零 / 1 回零中 / 2 成功
- `GA_HomeSns(int)` — 按位，1 = 电平取反
- `GA_ZeroPos(short, short)`、`GA_SetPrfPos(short, int)`
- `GA_GetAxisEncPos(short, ref double, short, ref int)`

实现：
